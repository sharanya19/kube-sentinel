# Monitoring

## Overview
Deploys and configures Kube-Sentinel's in-cluster observability and alerting stack inside the `monitoring` Kubernetes namespace (see [README.md](./README.md)). Installs Prometheus, Alertmanager, Grafana, node-exporter, and kube-state-metrics (`kube-prometheus-stack`), Monolithic-mode Grafana Loki for log storage and log-rule evaluation, and Grafana Alloy for pod log and Kubernetes event collection, along with fast-firing metric (`PrometheusRule`) and log (`ConfigMap`) alert rules targeting the Online Boutique workload in the `default` namespace.

## Interface
- [install.sh](./install.sh) — Bash installer entrypoint executing `helm repo add`, `helm upgrade --install` for releases `kps`, `loki`, and `alloy` in namespace `monitoring`, and `kubectl apply -f alert-rules.yaml -f loki-rules.yaml` `[install.sh:KPS_VERSION]`, `[install.sh:LOKI_VERSION]`, `[install.sh:ALLOY_VERSION]`, `[install.sh:helm upgrade]`, `[install.sh:kubectl apply]`.
- [prometheus-values.yaml](./prometheus-values.yaml) — Helm values for `prometheus-community/kube-prometheus-stack` (`93.2.0`): configures `15s` scrape interval, `3d` retention, cluster-wide rule/monitor discovery, Grafana credentials (`admin` / `kube-sentinel`) with pre-wired `Loki` datasource (`uid: loki`), and disables unreachable minikube control-plane targets `[prometheus-values.yaml:prometheusSpec]`, `[prometheus-values.yaml:alertmanagerSpec]`, `[prometheus-values.yaml:grafana]`.
- [loki-values.yaml](./loki-values.yaml) — Helm values for `grafana-community/loki` (`21.2.1`): configures `deploymentMode: Monolithic` (`singleBinary.replicas: 1`), `auth_enabled: false`, local filesystem TSDB (`v13`) with `72h` retention, rules sidecar (`k8s-sidecar-target-directory`), and Loki `rulerConfig` forwarding to Alertmanager v2 `[loki-values.yaml:deploymentMode]`, `[loki-values.yaml:loki]`, `[loki-values.yaml:rulerConfig]`, `[loki-values.yaml:sidecar]`.
- [alloy-values.yaml](./alloy-values.yaml) — Helm values for `grafana/alloy` (`1.15.0`): single-replica `deployment` running `discovery.kubernetes "pods"`, `discovery.relabel "pods"` (labels `namespace`, `pod`, `container`, `app`, `node`), `loki.source.kubernetes "pods"`, `loki.source.kubernetes_events "events"` (`job_name = "kubernetes-events"`), and `loki.write "default"` `[alloy-values.yaml:alloy.configMap.content]`, `[alloy-values.yaml:controller]`.
- [alert-rules.yaml](./alert-rules.yaml) — `PrometheusRule` `kube-sentinel-shop` (namespace `monitoring`, group `kube-sentinel-shop`) defining five metric alerts on `namespace="default"`: `ShopDeploymentScaledToZero` (`for: 1m`, `severity: critical`), `ShopDeploymentUnavailable` (`for: 1m`, `severity: critical`), `ShopPodWaiting` (`for: 1m`, `severity: warning`), `ShopPodRestarting` (`[10m] >= 2`, `severity: warning`), and `ShopRolloutStuck` (`for: 3m`, `severity: warning`) `[alert-rules.yaml:kube-sentinel-shop]`, `[alert-rules.yaml:ShopDeploymentScaledToZero]`, `[alert-rules.yaml:ShopDeploymentUnavailable]`, `[alert-rules.yaml:ShopPodWaiting]`, `[alert-rules.yaml:ShopPodRestarting]`, `[alert-rules.yaml:ShopRolloutStuck]`.
- [loki-rules.yaml](./loki-rules.yaml) — `ConfigMap` `kube-sentinel-log-rules` (namespace `monitoring`, key `shop-log-rules.yaml`, group `kube-sentinel-shop-logs`) defining log alert `ShopErrorLogs` (`for: 1m`, `severity: warning`) when error/exception/timeout log lines in `{namespace="default"}` exceed 5 per `app` in `5m` (excluding `visa` and `# reqs|# fails` noise) `[loki-rules.yaml:kube-sentinel-log-rules]`, `[loki-rules.yaml:ShopErrorLogs]`.
- Subdirectories: None.

## Invariants
- `install.sh` runs with `set -euo pipefail` relative to its own directory (`cd "$(dirname "$0")"`) and pins exact Helm chart versions (`KPS_VERSION="93.2.0"`, `LOKI_VERSION="21.2.1"`, `ALLOY_VERSION="1.15.0"`) `[install.sh:set]`, `[install.sh:KPS_VERSION]`, `[install.sh:LOKI_VERSION]`, `[install.sh:ALLOY_VERSION]`.
- All observability releases and rule resources reside in namespace `monitoring`, whereas every metric and LogQL alert expression scopes queries to `namespace="default"` `[install.sh:helm upgrade]`, `[alert-rules.yaml:kube-sentinel-shop]`, `[loki-rules.yaml:ShopErrorLogs]`.
- `ruleSelectorNilUsesHelmValues`, `serviceMonitorSelectorNilUsesHelmValues`, and `podMonitorSelectorNilUsesHelmValues` must remain `false` so Prometheus loads standalone `PrometheusRule` objects such as `kube-sentinel-shop` without requiring Helm release labels `[prometheus-values.yaml:ruleSelectorNilUsesHelmValues]`, `[prometheus-values.yaml:serviceMonitorSelectorNilUsesHelmValues]`, `[prometheus-values.yaml:podMonitorSelectorNilUsesHelmValues]`.
- Because Loki runs unauthenticated (`auth_enabled: false`), log rule `ConfigMap`s must include label `loki_rule: "1"` and annotation `k8s-sidecar-target-directory: /rules/fake` matching `sidecar.rules.folderAnnotation` so rules mount under the single-tenant `fake` directory `[loki-values.yaml:auth_enabled]`, `[loki-values.yaml:folderAnnotation]`, `[loki-rules.yaml:loki_rule]`, `[loki-rules.yaml:k8s-sidecar-target-directory]`.
- Cross-service endpoints depend on stable in-cluster DNS names `http://loki.monitoring.svc.cluster.local:3100` (Grafana datasource and Alloy `/loki/api/v1/push`) and `http://kps-kube-prometheus-stack-alertmanager.monitoring.svc.cluster.local:9093` (Loki ruler Alertmanager v2 target) `[prometheus-values.yaml:additionalDataSources]`, `[alloy-values.yaml:loki.write]`, `[loki-values.yaml:alertmanager_url]`.
- Control-plane scrapers (`kubeEtcd`, `kubeControllerManager`, `kubeScheduler`, `kubeProxy`) must remain `enabled: false` on minikube to avoid false target-down alerts `[prometheus-values.yaml:kubeEtcd]`, `[prometheus-values.yaml:kubeControllerManager]`, `[prometheus-values.yaml:kubeScheduler]`, `[prometheus-values.yaml:kubeProxy]`.

## Side Effects
- Adds Helm chart repositories (`prometheus-community`, `grafana`, `grafana-community`) over HTTPS and updates the local Helm repository cache `[install.sh:helm repo add]`, `[install.sh:helm repo update]`.
- Creates the `monitoring` namespace and mutates cluster state by installing/upgrading Helm releases `kps`, `loki`, and `alloy` (`--wait` timeouts `10m`, `10m`, `5m`) and applying `PrometheusRule/kube-sentinel-shop` and `ConfigMap/kube-sentinel-log-rules` `[install.sh:helm upgrade]`, `[install.sh:kubectl apply]`.
- Streams pod stdout/stderr logs and Kubernetes events via the Kubernetes API in Alloy and pushes them over HTTP to Loki, persisting TSDB/WAL/compactor state (`72h` retention) and Prometheus TSDB data (`3d` retention) to pod storage `[alloy-values.yaml:loki.source.kubernetes]`, `[alloy-values.yaml:loki.source.kubernetes_events]`, `[alloy-values.yaml:loki.write]`, `[loki-values.yaml:storage]`, `[loki-values.yaml:retention_period]`, `[prometheus-values.yaml:retention]`.
- Evaluates LogQL alert rules every `30s` in Loki's ruler and dispatches firing alerts over HTTP to Alertmanager v2 `[loki-values.yaml:rulerConfig]`.
